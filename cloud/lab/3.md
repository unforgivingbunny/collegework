## 1. Завдання попередньої підготовки (Prerequisite Tasks)

### Відповіді на питання (Answers to Questions):

#### 1.1. Core Concepts and Terms (from Video 1)
- **Global Infrastructure:**
  - **AWS Region:** A physical geographic location in the world where AWS has multiple, isolated Availability Zones (e.g., `us-east-1`, `eu-central-1`).
  - **Availability Zone (AZ):** One or more discrete data centers with redundant power, networking, and connectivity in an AWS Region.
  - **Edge Locations:** Content delivery network (CDN) endpoints used by Amazon CloudFront to cache content closer to end-users for lower latency.
- **Service Categories and Core Services:**
  - **Compute:** Amazon EC2 (virtual servers), AWS Lambda (serverless functions), AWS Fargate.
  - **Storage:** Amazon S3 (object storage), Amazon EBS (block storage for EC2), Amazon EFS (file storage).
  - **Databases:** Amazon RDS (relational databases), Amazon DynamoDB (NoSQL database).
  - **Networking:** Amazon VPC (virtual private networks), AWS Route 53 (DNS service), CloudFront.
  - **Management & Security:** AWS IAM (identity and access control), Amazon CloudWatch (monitoring), AWS Budgets.
- **Pricing & Billing:** *Pay-as-you-go* pricing model and *AWS Free Tier* offering free usage tiers for 12 months.

#### 1.2. Multi-Factor Authentication (MFA) and Configuration Options
- **Purpose of MFA:** Adds an extra layer of defense to secure AWS accounts by requiring a second authentication factor beyond just a username and password, protecting against unauthorized access.
- **MFA Options in AWS (from Video 2):**
  - **Authenticator App (Virtual MFA):** Time-based One-Time Password (TOTP) applications installed on mobile devices (e.g., Google Authenticator, Authy, Microsoft Authenticator).
  - **FIDO2 / Passkey / Hardware Security Key:** Physical USB security keys (e.g., YubiKey) supporting FIDO standards.
  - **Hardware TOTP Token:** Dedicated physical hardware tokens generating one-time passcodes.

#### 1.3. Amazon Budgets: Purpose and Setup Options
- **Purpose:** A service that allows users to track, monitor, and manage AWS costs and usage, sending automated alerts when thresholds are breached.
- **Setup Options (from Video 2):**
  - **Zero Spend Budget:** Notifies the user as soon as spent costs exceed $0.00 (ideal for staying strictly within Free Tier limits).
  - **Cost Budget:** Allows setting a specific monthly cost threshold (e.g., $10) and triggers notifications when actual or forecasted spend reaches a specified percentage (e.g., 80%).
  - **Usage Budget:** Tracks the utilization of specific service resources (e.g., EC2 instance hours).

#### 1.4. Purpose of IAM Policy and Managing User Permissions
- **Purpose:** An IAM Policy is a JSON document that explicitly defines permissions by specifying allowed (`Allow`) or denied (`Deny`) actions (`Actions`) on specific AWS resources (`Resources`).
- **Permission Setup:** Policies are attached to IAM Users, Groups, or Roles following the Principle of Least Privilege (granting only the necessary permissions required to perform specific tasks).

#### 1.5. Options for Attaching IAM Policies When Creating a New User
1. **Add user to group:** Adds the user to an existing user group that already has predefined policies attached (Best Practice).
2. **Copy permissions:** Copies permissions directly from an existing user account.
3. **Attach policies directly:** Attaches AWS Managed Policies or Custom Inline Policies directly to the user object.

#### 1.6. Writing and Applying Access Control via IAM Policies
IAM Policies are authored as JSON documents containing statements:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-bucket"
    }
  ]
}
```
Once defined, policies are attached to IAM entities (users, groups, roles) to dynamically enforce access controls across AWS APIs.

#### 1.7. Switching IAM Roles for Secure Access
Switching roles allows users to assume temporary security credentials with elevated or alternate permissions (e.g., accessing resources in another account or performing admin tasks) without creating new permanent credentials. In the AWS Management Console, users can navigate to the profile menu and select **Switch Role**, entering the target Account ID and Role Name.

#### 1.8. Permissions Boundaries for IAM Roles and Users
A **Permissions Boundary** is an advanced feature used to set the maximum permissions that an IAM entity (user or role) can receive. Even if an attached IAM policy grants full access (`AdministratorAccess`), the entity cannot perform actions outside the limits specified by its Permissions Boundary.

#### 1.9. Tracking and Analyzing User Actions with AWS CloudTrail
**AWS CloudTrail** records and logs all API calls, user activities, and administrative actions performed via the AWS Console, AWS CLI, or SDKs. It provides detailed audit trails containing event timestamps, request parameters, source IP addresses, and user identities for auditing and troubleshooting.

#### 1.10. IAM Policy Simulator Purpose
The **IAM Policy Simulator** is a testing tool provided by AWS to evaluate, test, and troubleshoot IAM policies. It allows administrators to verify whether specific API actions are allowed or denied for a user/role without executing real API commands in a production environment.

### 2.9. Довідник з використання AWS CLI (Cheat Sheet)

#### 1. Загальна структура команд
Будь-яка команда в AWS CLI будується за стандартним шаблоном:
```bash
aws <service-name> <command-name> [options/parameters]
```

#### 2. Корисні опції довідки (Help system)
- Довідка по всіх сервісах: `aws help`
- Довідка по конкретному сервісу: `aws ec2 help`
- Довідка по конкретній команді сервісу: `aws ec2 run-instances help`

#### 3. Базові команди для роботи

##### Налаштування та ідентифікація:
```bash
# Конфігурація ключів доступу
aws configure

# Перевірка поточного авторизованого профілю
aws sts get-caller-identity
```

##### Робота з обчислювальними ресурсами (EC2):
```bash
# Переглянути всі екземпляри віртуальних машин
aws ec2 describe-instances

# Переглянути лише ID та стан запущенних машин у формати таблиці
aws ec2 describe-instances --query "Reservations[*].Instances[*].[InstanceId,State.Name]" --output table
```

##### Робота зі сховищем (S3):
```bash
# Переглянути список бакетів
aws s3 ls

# Завантажити файл у бакет
aws s3 cp myfile.txt s3://my-bucket-name/
```

#### 4. Формати виводу (Output formats)
1. `json` (за замовчуванням) — детальний формат для парсингу та скриптів.
2. `text` — простий текстовий формат для регулярних виразів bash (`grep`, `awk`).
3. `table` — зручна таблична форма для читання людиною.

## 3. Контрольні питання (Review Questions)

### 3.1. What is the essence of TOTP authentication? Provide examples.
**TOTP (Time-based One-Time Password)** is a computer algorithm that generates a temporary single-use password based on the current time and a shared secret key.
- **Core Concept:** The authentication code automatically refreshes every 30 seconds. Both the server and the user client app stay time-synchronized (using UTC) to independently generate matching security codes.
- **Examples:** Google Authenticator, Authy, Microsoft Authenticator, 1Password.

### 3.2. Describe the JSON format: where is it used, and what are its features? Is JSON used in AWS?
**JSON (JavaScript Object Notation)** is an open, lightweight text-based data interchange format designed to be easy for humans to read/write and easy for machines to parse.
- **Features:** Built on two primary structures: collection of key-value pairs (`{ "Key": "Value" }`) and ordered lists of values or arrays (`[ "item1", "item2" ]`).
- **Usage in AWS:** Yes, JSON is heavily used across AWS for defining access control policies (IAM Policies), configuring CloudFormation templates, formatting AWS CLI responses, and structuring REST API payloads.

### 3.3. What types of Amazon APIs exist? Briefly describe them.
1. **Control Plane APIs:** Used to manage, provision, configure, and orchestrate infrastructure resources (e.g., creating an S3 bucket or modifying an RDS database).
2. **Data Plane APIs:** Used to interact directly with the data stored inside resources (e.g., uploading an object via `PutObject` into S3 or reading an entry via `GetItem` from DynamoDB).
3. **REST/HTTP APIs:** Standard web APIs provided via HTTPS endpoints to interact with serverless and microservice architectures (e.g., managed via Amazon API Gateway).

### 3.4. How can AWS CLI be installed across different Operating Systems?
- **Windows:** Download and run the official 64-bit MSI installer, or install via Windows Package Manager: `winget install Amazon.AWSCLI`.
- **macOS:** Download the official PKG installer package, or use Homebrew package manager: `brew install awscli`.
- **Linux:** Download the `.zip` installer bundle, unzip it, and run the installation script (`sudo ./aws/install`), or install via native distribution repositories (`sudo apt install awscli`).

### 3.5. Review basic AWS CLI commands. Provide examples.
- `aws configure` — Configures credentials, default region, and output formats.
- `aws sts get-caller-identity` — Returns details about the current authenticated user/role identity.
- `aws s3 ls` — Lists all Amazon S3 buckets.
- `aws ec2 describe-instances` — Retrieves details about existing EC2 virtual machine instances.
- `aws iam list-users` — Returns a list of all IAM users registered in the AWS account.
