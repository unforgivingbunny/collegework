## 1. Завдання попередньої підготовки (Prerequisite Tasks)

### Відповіді на питання (Answers to Questions):

#### 1.1. Purpose of Azure Marketplace Images and Custom Images Differences
* **Azure Marketplace Images:** Pre-configured OS and software templates provided by Microsoft or certified third-party vendors (e.g., Canonical Ubuntu, Red Hat Enterprise Linux, Microsoft Windows Server) allowing rapid deployment of standard server environments.
* **Public vs. Custom Images:**
  * **Public Marketplace Images:** Globally accessible templates maintained and updated by vendors for general enterprise use.
  * **Custom Images (Shared Image Gallery / Azure Compute Gallery):** Private images captured from customized Azure VMs that contain proprietary software, specific user accounts, security policies, and internal business configurations.

#### 1.2. Purpose of Azure Managed Disks and Supported Disk Types
* **Purpose of Azure Managed Disks:** Managed Disks are block-level storage volumes abstracted and managed by Microsoft Azure. Azure handles disk creation, hardware redundancy, and underlying storage account provisioning automatically.
* **Supported Disk Types in Azure:**
  * **Ultra Disk Storage:** Extremely high throughput and IOPS for top-tier, data-intensive workloads (SAP HANA, top-tier SQL databases).
  * **Premium SSD v2 / Premium SSD:** High-performance, low-latency storage for production workloads.
  * **Standard SSD:** Cost-effective storage balanced for web servers and dev/test environments (eligible for Azure Free Account).
  * **Standard HDD:** Lowest-cost block storage backed by traditional magnetic drives, suitable for backup storage and infrequent access.

#### 1.3. Purpose of Azure Snapshots and Use Cases
* **Purpose:** A Snapshot is a point-in-time, read-only copy of an Azure Managed Disk.
* **Use Cases:** Used for disaster recovery backups, creating disk clones before performing major system/software upgrades, and preserving baseline states during dev/test cycles.

#### 1.4. Azure VM Sizes and Recommended Scenarios
1. **General Purpose (`B-series`, `D-series`):** Balanced CPU-to-memory ratio. `B-series` (e.g., `B1s`) provides burstable CPU usage ideal for web servers, dev environments, and student accounts.
2. **Compute Optimized (`F-series`):** High CPU-to-memory ratio suitable for high-traffic web servers and batch processing.
3. **Memory Optimized (`E-series`, `M-series`):** High memory capacity designed for in-memory databases (Redis) and relational database servers.
4. **GPU Accelerated (`NC-series`, `NV-series`):** Specialized VMs with NVIDIA GPUs for AI/ML training, video rendering, and 3D graphics.

#### 1.5. Free Account Supported Operating Systems (Windows / Linux / macOS)
* **Linux (Ubuntu Server 22.04 LTS / Debian 11 / CentOS):** Supported under the `B1s` size (750 hours/month free). Default disk allocation: 30 GB Standard SSD/HDD.
* **Windows (Windows Server 2022 / 2019 Datacenter):** Supported under `B1s` size (750 hours/month free). Comes pre-configured with Remote Desktop Protocol (RDP) on TCP port 3389.
* **macOS:** macOS workloads are **not** supported natively on Azure VM Free Tier instances due to Apple hardware licensing requirements (available only via specialized bare-metal hosts outside Free Tier).

## 3. Контрольні питання (Review Questions)

### 3.1. What role do SSH keys or passwords play when connecting to an Azure Virtual Machine?
* **SSH Keys (Linux):** Use public-key cryptography (Public key on VM, Private key on local machine) providing secure, passwordless authentication immune to brute-force attacks.
* **Passwords (Windows/Linux):** Act as standard credential-based authentication used primarily for Windows RDP logins or Linux console fallbacks.

### 3.2. Which command is used to connect to a Linux VM in Azure via SSH?
`ssh -i /path/to/private-key.pem azureuser@<Public-IP-Address>`  
*Example:* `ssh -i ~/.ssh/azure_key.pem azureuser@20.238.112.45`

### 3.3. How else can you connect to a Linux Virtual Machine in Azure?
1. **Azure Serial Console:** Direct text console access embedded in Azure Portal for recovery and troubleshooting.
2. **Azure Bastion:** Managed RDP/SSH service providing secure browser connectivity over TLS without public IP exposure.
3. **SSH via Azure CLI (`az ssh vm`):** Native Azure CLI extension allowing SSH connections via Microsoft Entra ID authentication.

### 3.4. How can you connect to a Windows Virtual Machine in Azure?
1. **RDP (Remote Desktop Protocol):** Connect using a standard Windows GUI client (`mstsc.exe`) over port 3389.
2. **Azure Bastion:** HTML5 browser-based desktop stream directly in Azure Portal.
3. **PowerShell Remoting / WinRM:** Command-line management over HTTPS.

### 3.5. What is the difference between Stop (Deallocate) and Delete states for an Azure Virtual Machine?
* **Stop (Deallocated):** Compute resources (CPU/RAM) are released and billing for compute stops. Managed Disks and Static Public IPs remain allocated and incur minor storage charges. The VM can be started again anytime.
* **Delete:** Permanently removes the VM compute object, NICs, and optionally attached Managed Disks. All allocated dynamic resources are purged.
