## 1. Завдання попередньої підготовки (Prerequisite Tasks)

### Відповіді на питання (Answers to Questions):

#### 1.1. Що таке віртуальна машина та які особливості їх реалізації у Google Compute Engine?
**Virtual Machine (VM)** is a software emulation of a physical computer that runs an operating system and applications. In **Google Compute Engine (GCE)**, VMs are implemented as flexible, high-performance instances running on Google's global infrastructure. Key features include custom machine types (ability to fine-tune vCPU and memory), live migration of virtual instances for maintenance without downtime, fast boot times, and integration with high-performance persistent disks.

#### 1.2. Які можливості надає Google App Engine для розгортання веб-застосунків?
**Google App Engine (GAE)** is a fully managed, serverless platform for developing and deploying scalable web applications and mobile backends. It eliminates infrastructure management tasks, automatically provisions servers, scales instances up and down based on traffic load, and supports multiple programming languages (Python, Java, Node.js, Go, PHP, .NET) through Standard and Flexible environments.

#### 1.3. Які основні кроки створення App Engine-додатка через Google Cloud Console?
To create an App Engine application:
1. Navigate to the Google Cloud Console and select or create a project.
2. Open the App Engine dashboard or run the initialization command (`gcloud app create`).
3. Select a region for storing your application data.
4. Upload your application code configuration (`app.yaml`) via Cloud SDK or deploy it directly using the console tools.

#### 1.4. Які особливості реалізації Identity and Access Management (IAM) у GCP?
**Cloud IAM** in GCP allows administrators to authorize who can take action on specific resources, providing centralized access control. Its core features include role-based access control (RBAC) utilizing primitive, predefined, and custom roles, policy bindings attached to resources (hierarchical resource model from organization to project level), and comprehensive audit logging.

#### 1.5. Розкрийте використання версій (Versions) у App Engine для управління оновленнями додатків.
App Engine allows deploying multiple **Versions** of a service simultaneously. This enables seamless, zero-downtime updates through traffic splitting (e.g., canary deployments or A/B testing), instant rollbacks to a stable previous version if an error occurs, and isolated testing of new application features in separate environments.

#### 1.6. Здійсніть огляд Cloud Storage та його ключових функцій.
**Cloud Storage** is a managed service for storing unstructured data in GCP. Key features include global accessibility, high durability (99.999999999%), object versioning, customer-managed encryption keys (CMEK), lifecycle management rules to automatically transition data between storage classes, and granular access control via IAM and Access Control Lists (ACLs).

#### 1.7. Охарактеризуйте різні класи сховищ у GCP: Standard, Nearline, Coldline, Archive.
* **Standard Storage:** High-performance storage best for frequently accessed data ("hot" data).
* **Nearline Storage:** Low-cost, highly-durable storage for data accessed less than once a month (minimum 30-day storage duration).
* **Coldline Storage:** Lower-cost storage for data accessed less than once a quarter (minimum 90-day storage duration).
* **Archive Storage:** The lowest-cost, highly durable storage service for data archiving, disaster recovery, and data retention, intended for data accessed less than once a year (minimum 365-day storage duration).

#### 1.8. Опишіть, як працювати з Cloud Storage на прикладі використання мови Python або C#.
Working with Cloud Storage in Python involves utilizing the official `google-cloud-storage` library. Typical operations include initializing a client, creating buckets, uploading files (`blob.upload_from_filename`), downloading blobs, and managing permissions programmatically using service account credentials.

#### 1.9. Що таке Serverless та особливості його реалізації у Cloud Functions і Cloud Run?
**Serverless computing** is a cloud computing execution model where the cloud provider dynamically manages the allocation and provisioning of servers. 
* **Cloud Functions** is a lightweight, event-based serverless compute service designed for single-purpose functions triggered by cloud events.
* **Cloud Run** is a managed compute platform that enables running stateless containers invocable via HTTP requests or events, scaling automatically from zero to many containers.

#### 1.10. Поясніть різницю між автентифікацією та авторизацією. Як поняття IAM Roles і Service Accounts у GCP пов’язані з цими процесами?
**Authentication** verifies *who* you are, while **Authorization** determines *what* resources and actions you are allowed to access. In GCP, authentication is handled via Google Accounts or **Service Accounts** (special accounts used by applications/virtual machines rather than humans). Authorization is managed through **IAM Roles** containing specific permissions assigned to those accounts or users.

```bash
# Перегляд усіх віртуальних машин
gcloud compute instances list

# Створення нової віртуальної машини
gcloud compute instances create my-vm --zone=europe-west1-b --machine-type=e2-micro

# Зупинка віртуальної машини
gcloud compute instances stop my-vm --zone=europe-west1-b

# Видалення віртуальної машини
gcloud compute instances delete my-vm --zone=europe-west1-b
```

## 3. Контрольні питання (Review Questions)

### 3.1. У чому полягає принцип роботи TOTP-аутентифікації? Наведіть приклади в контексті Google Authenticator і 2-Step Verification.
**TOTP (Time-based One-Time Password)** algorithm generates a temporary passcode derived from a shared secret key and the current Unix time. In Google Authenticator and 2-Step Verification, the app computes a 6-digit code that changes every 30 seconds, providing secure multi-factor authentication.

### 3.2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у GCP?
**JSON (JavaScript Object Notation)** is a lightweight data-interchange format based on key-value pairs and ordered lists. It is widely used for configuration files, API responses, and data exchange. In GCP, JSON is heavily used for Service Account key files (`.json`), IAM policies, Cloud Logging structures, and deployment templates.

### 3.3. Які основні API надає Google Cloud Platform? Коротко охарактеризуйте їх призначення.
GCP provides multiple APIs including:
* **Compute Engine API:** Management of virtual machines and disks.
* **Cloud Storage API:** Object storage management and file operations.
* **BigQuery API:** Large-scale data analysis and SQL queries over petabytes of data.
* **Cloud IAM API:** Identity and access management configuration.

### 3.4. Як можна встановити Google Cloud SDK (CLI) під різними операційними системами?
Google Cloud SDK can be installed via:
* **Windows:** Using the interactive Google Cloud CLI installer (.msi package) or via PowerShell.
* **macOS:** Using Homebrew (`brew install --cask google-cloud-sdk`) or direct tarball extraction.
* **Linux (Debian/Ubuntu):** Via apt package manager by adding the official Google Cloud SDK distribution repository.

### 3.5. Розгляньте базові команди gcloud CLI. Наведіть приклади з поясненнями.
* `gcloud auth login` — Authenticates the user session with Google Cloud.
* `gcloud config set project [PROJECT_ID]` — Sets the active project for subsequent CLI commands.
* `gcloud compute instances list` — Lists all Compute Engine virtual machine instances active in the current zone/project.
