## 1. Завдання попередньої підготовки (Prerequisite Tasks)

### Відповіді на питання (Answers to Questions):

#### 1.1. Purpose of Google Compute Engine (GCE) in GCP
* **Google Compute Engine (GCE)** is an Infrastructure-as-a-Service (IaaS) component of Google Cloud Platform that provides highly customizable virtual machines (VMs) running on Google’s infrastructure. It allows users to run large-scale workloads, host web applications, manage databases, and perform complex calculations with flexible vCPU, memory, and storage configurations.

#### 1.2. Machine Images in GCP: Standard vs Custom Images
* **Machine Images:** Digital templates containing an operating system environment, disk state, global configuration settings, and application software used to provision new VMs.
* **Standard Images:** Official OS templates maintained by Google or certified partners (e.g., Ubuntu, Debian, CentOS, Windows Server).
* **Custom Images:** User-created private images captured from existing configured instances, used to duplicate environments with pre-installed enterprise software and custom security policies.

#### 1.3. Purpose of Persistent Disks and Disk Types (Standard, Balanced, SSD)
* **Purpose:** **Persistent Disks** are durable network-attached block storage devices that exist independently of the VM lifecycle.
* **Disk Types and Differences:**
  * **Standard Persistent Disk (`pd-standard`):** Efficient, low-cost HDD storage for sequential I/O and cold storage.
  * **Balanced Persistent Disk (`pd-balanced`):** Cost-effective SSD storage providing a balance between performance and cost for general workloads.
  * **SSD Persistent Disk (`pd-ssd`):** High-performance storage designed for enterprise databases, latency-sensitive applications, and high IOPS requirements.

#### 1.4. Snapshots in Google Cloud and Usage Scenarios
* **Snapshots:** Incremental, point-in-time backups of persistent disks stored redundantly across regions in Cloud Storage.
* **Use Cases:** Used for disaster recovery, system backups prior to software upgrades, and reproducing disk states across different zones or projects.

#### 1.5. GCP Machine Types (e2, n2, n2-highmem, n2-highcpu)
* **General Purpose (`e2`, `n2`):** Balanced compute-to-memory ratio. `e2-micro` is ideal for lightweight web servers and student accounts under Free Tier.
* **High-Memory (`n2-highmem`):** Increased memory per vCPU, optimized for in-memory databases (Redis) and heavy data processing.
* **High-CPU (`n2-highcpu`):** Increased vCPU ratio, suitable for high-performance computing, video encoding, and batch processing.

#### 1.6. Supported OS Distributions in Google Cloud Free Tier
* **Linux:** Ubuntu Server (22.04 LTS / 24.04 LTS), Debian (11 / 12), CentOS Stream, Rocky Linux. Eligible under `e2-micro` instance sizing.
* **Windows:** Windows Server 2019 / 2022 Datacenter. Supported with pre-configured RDP access (note: OS licensing cost applies outside standard free credit allocations).

#### 1.7. Purpose of Firewall Rules in GCP
* **Firewall Rules:** Network security specifications controlling inbound (ingress) and outbound (egress) connections to VM instances based on IP protocol, ports, and source/destination tags.

#### 1.8. Connection Methods: SSH vs RDP
* **SSH (Secure Shell):** Command-line encrypted terminal interface used for managing Linux VMs (TCP port 22).
* **RDP (Remote Desktop Protocol):** Graphical user interface connection used for managing Windows Server VMs (TCP port 3389).

## 3. Контрольні питання (Review Questions)

### 3.1. What role do SSH keys and passwords play when connecting to VMs in GCP?
* **SSH Keys (Linux):** Use asymmetric encryption. GCP automatically injects public keys into Linux instances via project-level or instance-level metadata, ensuring secure key-based access without static passwords.
* **Passwords (Windows):** Windows VMs rely on administrative passwords, which are securely generated via GCP metadata mechanisms (`Set Windows password`) and decrypted for RDP logins.

### 3.2. Which command is used to connect to a Linux VM via gcloud CLI?
`gcloud compute ssh <vm-name> --zone=<zone-name>`  
*Example:* `gcloud compute ssh linux-prykhodko-team --zone=europe-west1-b`

### 3.3. What connection methods are available for Linux VMs in GCP?
1. **GCP Console SSH in Browser:** Web-based SSH terminal directly embedded in the browser.
2. **`gcloud compute ssh`:** CLI-based SSH wrapper handling key management automatically.
3. **Standard SSH Client:** Traditional terminal SSH using custom key pairs via public IP or Identity-Aware Proxy (IAP).

### 3.4. How can you connect to a Windows VM in GCP?
1. **RDP Client (`mstsc`):** Standard Remote Desktop connection using external IP and generated credentials.
2. **Chrome RDP Extension / IAP Desktop:** Secure RDP streaming over TLS via Identity-Aware Proxy without exposing public port 3389.

### 3.5. What is the difference between Stop and Delete states for a VM?
* **Stop:** Compute resources (vCPU/RAM) are released and billing for compute stops. Persistent disks and static External IPs remain attached, incurring minor storage charges.
* **Delete:** Permanently purges the VM instance and its associated boot persistent disk.

### 3.6. What is the purpose of a Startup script during VM creation?
A **Startup script** executes administrative commands automatically upon VM initialization. It automates package installation, software configurations, security updates, and web server deployments without requiring manual SSH sessions.

### 3.7. How can you allow or deny inbound traffic to a VM in GCP?
Inbound traffic is managed through **VPC Firewall Rules**. Rules can be applied globally, to network tags (e.g., `http-server`), or to specific Service Accounts, specifying target IP ranges (e.g., `0.0.0.0/0`), protocols (TCP/UDP), and ports (80, 443, 3389).
