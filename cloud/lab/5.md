## Практичне завдання №1. Огляд Storage-as-a-Service (Amazon S3)

### Відповіді на запитання:

#### 1. В чому суть концепції Storage-as-a-Service, коли її доцільно використовувати?
- **Essence of Storage-as-a-Service (STaaS):** STaaS is a cloud computing business model where a service provider (like AWS) offers scalable object, block, or file storage infrastructure over the Internet on a pay-as-you-go basis. Organizations avoid purchasing and maintaining physical SAN/NAS hardware.
- **When to use:** It is ideal for storing unstructured data (media files, documents), hosting static website assets, managing system backups, disaster recovery archives, and handling massive data sets for analytics.

#### 2. Наведіть приклади сервісів за моделлю Storage-as-a-Service
- **Amazon S3 (Simple Storage Service):** Scalable object storage for arbitrary files.
- **Amazon EBS (Elastic Block Store):** High-performance block storage volumes for EC2 instances.
- **Amazon EFS (Elastic File System):** Fully managed elastic file system for concurrent use with multiple instances via NFS.
- **Google Cloud Storage & Microsoft Azure Blob Storage:** Alternative multi-cloud STaaS implementations.

#### 3. Порівняйте поняття бакету та віртуальної машини на прикладі сервісів від AWS

| Параметр | Amazon S3 Bucket | Amazon EC2 Virtual Machine |
| :--- | :--- | :--- |
| **Хмарна модель** | Storage-as-a-Service / Serverless | Infrastructure-as-a-Service (IaaS) |
| **Обчислювальні ресурси** | Немає виділеного ОС/CPU/RAM для адміністрування | Повноцінна ОС (Linux/Windows), vCPU та RAM |
| **Масштабованість** | Автоматична масштабованість від байтів до петабайтів | Потребує вибору типу інстансу та Auto Scaling |
| **Управління** | Обслуговується повністю AWS (керування через API/Console) | Потребує оновлення ОС, патчів безпеки та брандмауера |

#### 4. Опишіть для чого потрібні такі дії над бакетами як Versioning, Lifecycle та Replication
- **Versioning:** Збереження кількох версій одного об'єкта в одному бакеті. Дозволяє відновлювати файли після випадкового видалення чи перезапису.
- **Lifecycle Rules:** Автоматизовані правила, які переводять об'єкти між класами зберігання (наприклад, з *S3 Standard* до дешевших *S3 Glacier*) або видаляють застарілі дані для оптимізації витрат.
- **Replication:** Автоматичне асинхронне копіювання об'єктів між бакетами S3 в різних регіонах (Cross-Region Replication) для підвищення відмовостійкості та резервування.

#### 5. Які методи захисту від несанкціонованого доступу до бакетів існують
1. **S3 Block Public Access:** Глобальний перемикач безпеки для блокування публічного доступу.
2. **Bucket Policies:** JSON-політики доступу безпосередньо на рівні бакету.
3. **Access Control Lists (ACLs):** Управління дозволами на рівні окремих об'єктів/бакетів.
4. **Data Encryption:** Шифрування даних під час зберігання (Server-Side Encryption) та передачі (HTTPS/TLS).

## Практичне завдання №2. Огляд Function-as-a-Service (FaaS)

### Відповіді на запитання:

#### 1. В чому суть концепції Function-as-a-Service (FaaS), коли її доцільно використовувати?
- **Concept:** FaaS allows developers to run modular pieces of code (functions) in response to specific events without provisioning, maintaining, or scaling servers. Billing is calculated strictly per millisecond of execution time.
- **Use cases:** Real-time file/image processing, IoT telemetry ingestion, lightweight API backends, database stream listeners, and cron-like scheduled tasks.

#### 2. Опишіть поняття “Serverless-архітектури”
- **Serverless Architecture:** Подхід до розробки ПЗ, при якому розробники створюють додатки без необхідності управління серверами. Вся інфраструктура, масштабування та безпека повністю адмініструються хмарним провайдером.

#### 3. Порівняйте поняття serverless-архітектури та Function-as-a-Service (FaaS)
- **Serverless Architecture** — це загальна концепція побудови систем, яка включає безсерверні обчислення, бази даних (DynamoDB), сховища (S3) та черги повідомлень (SQS).
- **FaaS** — це безпосередньо один із компонентів Serverless-архітектури, що відповідає за виконання коду у відповідь на події (наприклад, AWS Lambda).

#### 4. Наведіть приклади serverless-рішень та сервісів Function-as-a-Service (FaaS) у хмарних провайдерів

| Провайдер | FaaS Сервіс | Serverless NoSQL БД | Serverless Сховище | API Шлюз |
| :--- | :--- | :--- | :--- | :--- |
| **AWS** | AWS Lambda | Amazon DynamoDB | Amazon S3 | Amazon API Gateway |
| **Google Cloud** | Cloud Functions | Cloud Firestore | Cloud Storage | Cloud Endpoints |
| **Microsoft Azure** | Azure Functions | Azure Cosmos DB | Azure Blob Storage | Azure API Management |

#### 5. Наведіть приклад реальної ІТ-задачі, де можна використати модель Function-as-a-Service (FaaS) та розпишіть на прикладі платформи AWS, що для цього потрібно зробити
- **Задача:** Автоматична генерація зменшених копій зображень (thumbnails) при завантаженні на сайт.
- **Реалізація в AWS:**
  1. Користувач завантажує фото у бакет `input-photos-bucket` (S3).
  2. S3 генерує подію `s3:ObjectCreated:*` та викликає функцію **AWS Lambda**.
  3. Lambda завантажує фото, змінює розмір за допомогою бібліотеки Pillow та зберігає результат у бакет `thumbnails-bucket`.

## Практичне завдання №3. Робота з реляційними базами даних в AWS

### Відповіді на запитання:

#### 1. Опишіть можливості Amazon RDS (Relational Database Service). До якої хмарної моделі її можна віднести?
- **Features:** Amazon RDS є повністю керованим сервісом для реляційних баз даних. Він автоматизує рутинні задачі: налаштування обладнання, оновлення ОС, створення резервних копій, моніторинг та маштабування.
- **Service Model:** Належить до моделі **Platform-as-a-Service (PaaS)**.

#### 2. Які бази даних підтримує Amazon RDS. Порівняйте їх за можливостями
- **Amazon Aurora:** Хмарно-оптимізована БД, сумісна з MySQL та PostgreSQL. Забезпечує до 5x вищу продуктивність.
- **PostgreSQL / MySQL / MariaDB:** Популярні відкриті БД для стандартних веб-додатків.
- **Oracle / Microsoft SQL Server:** Корпоративні БД з підтримкою складних бізнес-систем та ліцензуванням.

#### 3. Порівняйте процес розгортання БД на базі Amazon RDS (PaaS-модель) та EC2 + MySQL (IaaS-модель). Коли доцільно використовувати їх

| Критерій | Amazon RDS (PaaS) | EC2 + MySQL (IaaS) |
| :--- | :--- | :--- |
| **Швидкість розгортання** | Кілька хвилин у консолі/CLI | Тривала ручна настройка ОС та СУБД |
| **Доступ до ОС** | Відсутній (повністю керовано AWS) | Повний root-доступ до ОС |
| **Бортове резервування** | Автоматичні Automated Snapshots | Ручні скрипти/бэкапи |
| **Сфера застосування** | 95% стандартних проектів | Потреба у кастомних модулях ОС |

#### 4. Опишіть для чого потрібні операції масштабування, створення снепшотів, моніторингу та логування баз даних
- **Масштабування:** Зміна класів інстансів (вертикальне) або додавання Read Replicas (горизонтальне) для обробки підвищеного навантаження.
- **Снепшоти:** Резервні копії БД для відновлення даних на певний момент часу (Point-in-time recovery).
- **Моніторинг та логування:** Відстеження навантаження на CPU/RAM та аналіз повільних запитів через CloudWatch та RDS Performance Insights.

#### 5. Порівняйте поняття реляційних та NoSQL баз даних. Чи підтримує NoSQL сервіс Amazon RDS
- **Реляційні (SQL):** Сувора таблична схема, підтримка транзакцій ACID, складні SQL-запити.
- **NoSQL:** Гнучка схема (JSON, Key-Value), висока швидкість запису, горизонтальне масштабування.
- **RDS підтримка:** Amazon RDS підтримує **тільки** реляційні бази даних. Для NoSQL використовується Amazon DynamoDB.

## Практичне завдання №4. Робота з NoSQL базами даних в AWS

### Відповіді на запитання:

#### 1. Наведіть класифікацію сучасних NoSQL баз даних. Де вони використовуються в хмарних технологіях?
1. **Key-Value Stores (Amazon DynamoDB):** Сесії користувачів, корзини інтернет-магазинів.
2. **Document Databases (Amazon DocumentDB):** Каталоги товарів, контент-менеджмент.
3. **Wide-Column Stores (Amazon Keyspaces):** Логи, аналітика великих обсягів даних.
4. **Graph Databases (Amazon Neptune):** Соціальні мережі, рекомендаційні системи.

#### 2. Опишіть можливості та застосування Amazon DynamoDB
- Fully managed serverless NoSQL database that provides single-digit millisecond latency at any scale. Built-in security, automated multi-region replication (Global Tables), and event streams.

#### 3. Опишіть основні поняття Amazon DynamoDB: Primary Key, WCU та RCU
- **Primary Key:** Унікальний ідентифікатор запису (Partition Key або Partition Key + Sort Key).
- **WCU (Write Capacity Unit):** Одиниця пропускної здатності запису (1 WCU = 1 запис/сек розміром до 1 КБ).
- **RCU (Read Capacity Unit):** Одиниця пропускної здатності читання (1 RCU = 1 суворо послідовне читання/сек розміром до 4 КБ).

#### 4. Порівняйте сервіси AWS для роботи з NoSQL базами даних - Amazon DynamoDB, Amazon DocumentDB та Amazon Keyspaces

| Сервіс | Модель даних | Сумісність | Основне призначення |
| :--- | :--- | :--- | :--- |
| **Amazon DynamoDB** | Key-Value / Document | Native AWS API | Serverless веб-додатки та ігри |
| **Amazon DocumentDB** | JSON Document | MongoDB compatible | Міграція існуючих проектів MongoDB |
| **Amazon Keyspaces** | Wide-Column | Apache Cassandra compatible | Міграція Cassandra та часові ряди |

#### 5. Наведіть приклади ІТ-задач, де буде доцільно використовувати Amazon DynamoDB, Amazon DocumentDB та Amazon Keyspaces. Як їх розгорнути в AWS
- **DynamoDB:** Зберігання списку лідерів у онлайн-грі (розгортається за лічені секунди через AWS Console/CLI).
- **DocumentDB:** Каталог товарів зі складними атрибутами (розгортається як кластер у середовищі Amazon VPC).
- **Keyspaces:** Збереження показань з мільйонів датчиків IoT (розгортається через ключові простори Keyspace).
