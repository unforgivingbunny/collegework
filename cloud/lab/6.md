## 1. Завдання попередньої підготовки (Prerequisite Tasks)

### Відповіді на запитання:

#### 1.1. Що таке віртуальна машина та які особливості їх реалізації у Azure Virtual Machine
* **Virtual Machine (VM)** is a software-based emulation of a physical computer running an operating system and applications.
* **Azure VM Features:** Supports Windows, Linux, custom images; offers various instance series (B-series for burstable, D-series for general purpose, NV/NC for GPU acceleration); integrates natively with Azure Virtual Networks (VNet), Managed Disks, and Microsoft Entra ID (Azure AD).

#### 1.2. Які можливості надає Azure App Service?
* Fully managed **Platform-as-a-Service (PaaS)** for hosting web applications, REST APIs, and mobile backends.
* **Key capabilities:** Auto-scaling (horizontal and vertical), continuous deployment (GitHub Actions, Azure DevOps), custom domain & SSL binding, multi-language support (.NET, Java, Node.js, Python, PHP), deployment slots, and built-in diagnostic logging.

#### 1.3. Які основні кроки створення App Service через портал Azure?
1. Open Azure Portal (`portal.azure.com`) and select **Create a resource > Web App**.
2. Select Subscription, Resource Group, enter unique App Name.
3. Select Runtime stack (e.g., Node.js, .NET 8, Python) and Operating System (Linux/Windows).
4. Select Region and App Service Plan (Pricing Tier: Free F1, Basic, or Standard).
5. Review settings and click **Create**.

#### 1.4. Які особливості реалізації "Access control (IAM)" в Azure?
* Based on **Azure RBAC (Role-Based Access Control)** to manage *who* has access to Azure resources, *what* they can do, and *what areas* they can access.
* **Key concepts:**
  * **Role Definition:** A collection of permissions (Built-in roles: *Owner*, *Contributor*, *Reader*).
  * **Scope:** The boundary where permissions apply (Management Group > Subscription > Resource Group > Resource).
  * **Role Assignment:** Attaching a role to a security principal (User, Group, Service Principal, Managed Identity).

#### 1.5. Розкрийте використання Deployment slots для управління версіями
* **Deployment Slots** are live web apps with their own hostnames used for staging and testing before production.
* **Usage:** Code is deployed to a staging slot (`my-app-staging.azurewebsites.net`), verified, and then swapped with the production slot instantly with zero downtime. If issues occur, the swap can be rolled back immediately.

#### 1.6. Здійсніть огляд Storage Account та його ключових функцій
* **Azure Storage Account:** A secure, centralized namespace providing high availability, durability, and scalability for cloud data objects.
* **Key features:** Encryption-at-rest (SSE), geo-redundancy (LRS, ZRS, GRS), lifecycle management policies, static website hosting, and secure access via Shared Access Signatures (SAS) or Access Keys.

#### 1.7. Охарактеризуйте різні типи сховищ в Azure Storage Account
1. **Blob Storage:** Massive object storage for unstructured data (images, videos, backups).
2. **File Storage:** Fully managed cloud file shares accessible via SMB/NFS protocols.
3. **Table Storage:** NoSQL key-value store for rapid development and large unstructured datasets.
4. **Queue Storage:** Asynchronous message queuing for decoupling distributed application components.

#### 1.8. Опишіть як працювати з Azure Storage на прикладі використання мови C#
Using the official SDK package `Azure.Storage.Blobs`:
```csharp
using Azure.Storage.Blobs;

string connectionString = "<your-connection-string>";
BlobServiceClient blobServiceClient = new BlobServiceClient(connectionString);
BlobContainerClient containerClient = await blobServiceClient.CreateBlobContainerAsync("sample-container");

BlobClient blobClient = containerClient.GetBlobClient("document.txt");
await blobClient.UploadAsync("local-file.txt", true);
```

#### 1.9. Що таке Serverless та особливості їх реалізації у Azure Functions
* **Serverless:** Event-driven cloud execution model where infrastructure management is abstracted away, scaling automatically from 0 to thousands of instances, billing per execution time/memory.
* **Azure Functions Features:** Supports triggers (HTTP, Timer, Blob, Cosmos DB), bindings for seamless input/output data wiring without boilerplate code, and integration with Application Insights.

#### 1.10. Поясніть різницю між автентифікацією та авторизацією. Як пов'язані Azure RBAC та Entra ID з цими поняттями?
* **Authentication (AuthN):** Verifying *who you are* (e.g., logging in with password and MFA). Managed by **Microsoft Entra ID (formerly Azure AD)**.
* **Authorization (AuthZ):** Verifying *what you are allowed to do*. Managed by **Azure RBAC** by assigning permissions to identities verified by Entra ID.

### 2.9. Довідник з використання Azure CLI (Cheat Sheet)

#### 1. Загальна структура команд
Команди Azure CLI будуються за принципом:
```bash
az <group> [subgroup] <action> [parameters]
```

#### 2. Довідкова система
```bash
az --help                        # Загальна довідка
az vm --help                     # Довідка по віртуальним машинам
az storage account create --help # Довідка по конкретній команді
```

#### 3. Базові команди для роботи
```bash
# Авторизація та перевірка облікового запису
az login
az account show

# Управління ресурсовими групами (Resource Groups)
az group create --name MyResourceGroup --location westeurope
az group list --output table

# Робота з віртуальними машинами (Virtual Machines)
az vm create --resource-group MyResourceGroup --name MyVM --image Ubuntu2204 --admin-username azureuser --generate-ssh-keys
az vm list --output table
az vm stop --resource-group MyResourceGroup --name MyVM

# Формати виводу (--output / -o)
# Підтримувані варіанти: json, table, tsv, yaml
az vm list -o table
```

## 3. Контрольні питання (Review Questions)

### 3.1. В чому суть TOTP аутентифікації? Наведіть приклади в контексті Microsoft Authenticator та Azure MFA.
**TOTP (Time-based One-Time Password)** is a temporary, single-use passcode generated using a shared secret key and the current UTC timestamp.
- **Mechanism:** Refreshes every 30 seconds.
- **In Microsoft Authenticator / Azure MFA:** When logging into Azure, the server requests a 6-digit TOTP code or sends a push notification matching a number shown on screen.

### 3.2. Опишіть формат JSON: де він використовується, які його особливості. Чи застосовується цей формат у Azure?
**JSON (JavaScript Object Notation)** is a lightweight, human-readable data interchange format consisting of key-value pairs (`{ "key": "value" }`) and ordered arrays.
- **Usage in Azure:** JSON is heavily used in ARM (Azure Resource Manager) templates, Azure Policy definitions, Azure RBAC custom role definitions, and default output formats for Azure CLI commands.

### 3.3. Які є види Azure API? Коротко опишіть їх.
1. **Azure Resource Manager (ARM) REST API:** Control plane API used to create, update, and delete Azure resources.
2. **Data Plane APIs:** Service-specific APIs used to read/write actual data inside resources (e.g., Azure Blob Storage REST API, Cosmos DB SQL API).

### 3.4. Як можна встановити Azure CLI під різними операційними системами?
- **Windows:** Download and run the official MSI installer, or via PowerShell: `winget install Microsoft.AzureCLI`.
- **macOS:** Install via Homebrew: `brew install azure-cli`.
- **Linux (Ubuntu/Debian):** Run one-line curl installation script: `curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash`.

- `az vm list -o table` — List registered Virtual Machines in tabular format.
