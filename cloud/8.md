**Виконав студент групи РПЗ-34 Глядченко Олег**

## Частина 1. Творче завдання: Порівняння за 10 прикладними ІТ-задачами

### 1. Розгортання веб-сервера (Apache / Nginx)

*   **Переваги контейнерів (Docker/Podman):**
    *   Легковажність та висока швидкість запуску (секунди).
    *   Мінімальне споживання ресурсів (не потрібно піднімати окреме ядро ОС).
    *   Просте масштабування за допомогою оркестраторів (Kubernetes / Docker Swarm).
*   **Недоліки контейнерів:**
    *   Контейнери ділять ядро з хост-системою, що при помилках конфігурації потенційно знижує ізольованість порівняно з повноцінною ВМ.
*   **Переваги віртуалізації (KVM, ESXi, Hyper-V):**
    *   Повна ізоляція ресурсів та безпека на рівні апаратного забезпечення.
*   **Недоліки віртуалізації:**
    *   Повільний запуск (хвилини), значне накладне витрачання ОЗУ та диску на гостьову ОС.
*   **Висновок / Що обрати:** **Контейнери**. Стандартні веб-сервери безстатусні (stateless) і вимагають швидкого масштабування під навантаженням, для чого контейнеризація підходить ідеально.

---

### 2. Розгортання веб-застосунку з різними залежностями (Python 2 та Python 3)

*   **Переваги контейнерів:**
    *   Ізоляція оточення на рівні файлової системи: в одному контейнері пакується Python 2 зі старими бібліотеками, в іншому — Python 3.
    *   Відсутність конфліктів системних залежностей (DLL/so) на одній хостовій машині.
*   **Недоліки контейнерів:**
    *   Потрібно грамотно збирати Dockerfile для збереження легковажності образів.
*   **Переваги віртуалізації:**
    *   Дозволяє запустити додатки на абсолютно різних ОС, якщо Python 2 вимагає старого ядра Linux.
*   **Недоліки віртуалізації:**
    *   Витрачати цілу віртуальну машину лише заради ізоляції версії інтерпретатора — надто ресурсомістке рішення.
*   **Висновок / Що обрати:** **Контейнери**. Вони вирішують проблему «на моєму комп'ютері все працювало» найефективнішим шляхом.

---

### 3. Тестування програмного забезпечення на різних ОС (Windows / Linux)

*   **Переваги віртуалізації:**
    *   Можливість одночасно запустити повноцінну Windows 11, macOS та Ubuntu Linux на одному фізичному сервері/ПК.
    *   Тестування GUI-додатків, графічних драйверів, специфічних системних викликів.
*   **Недоліки віртуалізації:**
    *   Високі вимоги до обсягу оперативної пам'яті та дискового простору.
*   **Переваги контейнерів:**
    *   Чудово підходять для тестування крос-платформеного коду під різні дистрибутиви Linux (Alpine, Debian, RHEL).
*   **Недоліки контейнерів:**
    *   Неможливо запустити Windows-контейнер на Linux-ядері без шарів віртуалізації (наприклад, WSL2).
*   **Висновок / Що обрати:** **Класична віртуалізація**. Якщо потрібно тестувати ПЗ під різні операційні системи (особливо з графічним інтерфейсом), віртуальні машини є єдиним повноцінним рішенням.

---

### 4. Запуск застарілого програмного забезпечення (Legacy на старих версіях ОС)

*   **Переваги віртуалізації:**
    *   Підтримка застарілих ОС (наприклад, Windows XP, Windows Server 2003, старі ядра Linux), які не працюють на сучасному залізі.
    *   Повна еймуляція старого обладнання та системного оточення.
*   **Недоліки віртуалізації:**
    *   Потребує додаткових ресурсів на підтримку legacy-системи.
*   **Переваги контейнерів:**
    *   Майже непридатні, якщо застаріле ПЗ вимагає специфічного старого ядра ОС.
*   **Недоліки контейнерів:**
    *   Контейнери Linux залежать від ядра хост-системи. Старий бінарний файл може не запуститися на сучасному ядрі Linux.
*   **Висновок / Що обрати:** **Класична віртуалізація**. Забезпечує точну сумісність зі старим апаратним та програмним забезпеченням.

---

### 5. Навчання системному адмініструванню (встановлення, налаштування ОС)

*   **Переваги віртуалізації:**
    *   Повний цикл роботи з ОС: розбиття дисків (LVM/ZFS), налаштування завантажувача (GRUB), робота з модулями ядра, налаштування мережевих стеків і брандмауерів (iptables/nftables).
    *   Створення знімків стану (snapshots) для швидкого відкату при помилках.
*   **Недоліки віртуалізації:**
    *   Вимагає більше апаратних ресурсів від навчальних ПК.
*   **Переваги контейнерів:**
    *   Швидка видача середовища для практики з базовими командами bash або пакетами.
*   **Недоліки контейнерів:**
    *   У контейнері немає повноцінного процесу ініціалізації (`init`/`systemd`), немає власного ядра, обмежений доступ до пристроїв.
*   **Висновок / Що обрати:** **Класична віртуалізація**. Для отримання реальних навичок сисадміна необхідно працювати з повноцінною операційною системою.

---

### 6. CI/CD та автоматизоване тестування коду

*   **Переваги контейнерів:**
    *   Миттєве створення та знищення одноразових середовищ для тестування (ephemeral environments).
    *   Висока щільність упаковки: на одному сервері збірки можна запустити десятки паралельних тестів.
    *   Легка інтеграція з CI/CD інструментами (GitLab CI, GitHub Actions, Jenkins).
*   **Недоліки контейнерів:**
    *   Потрібно контролювати кешування шарів для оптимізації часу збірки.
*   **Переваги віртуалізації:**
    *   Високий рівень ізоляції для тестування потенційно небезпечного коду.
*   **Недоліки віртуалізації:**
    *   Тривалий час розгортання ВМ уповільнює пайплайни розробки.
*   **Висновок / Що обрати:** **Контейнери**. Вони є стандартом де-факто для сучасного CI/CD завдяки швидкості та відтворюваності.

---

### 7. Міграція монолітного додатку до мікросервісної архітектури

*   **Переваги контейнерів:**
    *   Ідеально відповідають концепції мікросервісів: один контейнер — один сервіс.
    *   Легке керування взаємозв'язками через Docker Compose або Kubernetes.
    *   Швидке оновлення окремих частин системи без зупинки всього моноліту.
*   **Недоліки контейнерів:**
    *   Вимагає переосмислення архітектури додатка та роботи з даними.
*   **Переваги віртуалізації:**
    *   Зручна для першого етапу «Lift and Shift» (перенесення моноліту як є), але не для самої мікросервісної розробки.
*   **Недоліки віртуалізації:**
    *   Незручно розгортати десятки дрібних сервісів у окремих ВМ через високі накладні витрати.
*   **Висновок / Що обрати:** **Контейнери**. Саме контейнеризація зробила мікросервісну архітектуру ефективною та популярною.

---

### 8. Запуск ресурсоємних або stateful-додатків (СУБД: PostgreSQL, Oracle)

*   **Переваги віртуалізації:**
    *   Гарантоване виділення ресурсів (CPU, RAM, dedicated I/O) без ризику впливу сусідніх процесів (Noisy Neighbor problem).
    *   Зручні механізми резервного копіювання, реплікації та Live Migration на рівні гіпервізора.
*   **Недоліки віртуалізації:**
    *   Невелика втрата продуктивності на трансляцію системних викликів.
*   **Переваги контейнерів:**
    *   Максимальна продуктивність I/O (при використанні direct volume mounts).
*   **Недоліки контейнерів:**
    *   Складність організації довготривалого збереження даних (persistent storage) та масштабування кластерів БД в оркестраторах.
*   **Висновок / Що обрати:** **Класична віртуалізація** (або Bare-Metal). Для великих продуктивних баз даних висока ізоляція та передбачуваність I/O класичних ВМ часто є перевагою.

---

### 9. Розгортання ML-моделей для аналізу даних (Machine Learning Inference)

*   **Переваги контейнерів:**
    *   Легке пакування складного оточення (Python, CUDA, PyTorch/TensorFlow, OpenCV).
    *   Можливість прямого прокидання GPU (NVIDIA Container Toolkit) у контейнер з мінімальними накладними витратами.
    *   Автоматичне горизонтальне масштабування в Kubernetes залежно від кількості запитів (HPA).
*   **Недоліки контейнерів:**
    *   Великий розмір підсумкових образів (через ML-бібліотеки та CUDA).
*   **Переваги віртуалізації:**
    *   Надійне прокидання графічного процесора (GPU Passthrough).
*   **Недоліки віртуалізації:**
    *   Складніше масштабувати під час пікових навантажень.
*   **Висновок / Що обрати:** **Контейнери**. Забезпечують гнучке масштабування та простоту розгортання моделей у хмарах.

---

### 10. Самостійний приклад: Запуск локального середовища розробки (Local Dev Environment)

*   **Опис завдання:** Створення ідентичного для всіх розробників команди середовища (база даних, кєш-сервер Redis, черги повідомлень RabbitMQ).
*   **Переваги контейнерів:**
    *   Конфігурація описується одним файлом `docker-compose.yml`.
    *   Розгортання всього стеку однією командою (`docker compose up`).
    *   Мінімальні вимоги до оперативної пам'яті ноутбука розробника.
*   **Недоліки контейнерів:**
    *   На macOS/Windows вимагає легкого шару віртуалізації для запуску Linux-ядра (Docker Desktop).
*   **Переваги віртуалізації:**
    *   Можливість створити повний аналог продакшн-сервера.
*   **Недоліки віртуалізації:**
    *   Високе навантаження на акумулятор та процесор ноутбука, тривале розгортання.
*   **Висновок / Що обрати:** **Контейнери**. Це стандарт для командної розробки, який гарантує однакове середовище у всіх учасників проекту.

## Частина 2. Словник термінів

| Термін | Розгорнуте визначення | ІТ-напрями та професії |
| :--- | :--- | :--- |
| **Монолітний додаток (Monolithic Architecture)** | Архітектура програмного забезпечення, у якій усі компоненти та функціональні блоки (авторизація, бізнес-логіка, робота з БД) об'єднані в єдиний кодову базу та виконуються як єдиний процес. | Software Engineer, Solutions Architect, Legacy Systems Specialist. |
| **Мікросервіси (Microservices Architecture)** | Архітектурний підхід, при якому додаток розбивається на набір дрібних, незалежних сервісів, що взаємодіють між собою через чітко визначені API (REST, gRPC) і можуть розгортатися окремо. | Backend Developer, Cloud Architect, DevOps Engineer. |
| **Stateful-додатки (Stateful Applications)** | Застосунки або сервіси, які зберігають стан та дані користувача між сесіями чи запитами (наприклад, СУБД, файлові сховища, брокери повідомлень з персистентністю). | Database Administrator (DBA), Data Engineer, Infrastructure Engineer. |
| **Stateless-додатки (Stateless Applications)** | Застосунки, які не зберігають свій стан на локальному диску чи в пам'яті. Кожен запит обробляється незалежно, що дозволяє безперешкодно знищувати або масштабувати екземпляри. | Web Developer, Frontend Engineer, Cloud Solutions Architect. |
| **Контейнер CI/CD (CI/CD Container)** | Ізольоване середовище виконання, яке створюється «на льоту» в системах безперервної інтеграції та доставки для автоматичної збірки, тестування та деплою коду. | DevOps Engineer, SRE (Site Reliability Engineer), QA Automation Engineer. |
| **Гіпервізор (Hypervisor)** | Спеціалізоване ПЗ або апаратне забезпечення, яке створює та керує віртуальними машинами, розділяючи фізичні ресурси (CPU, RAM, Storage) між ними. | System Administrator, Virtualization Admin, Cloud Infrastructure Engineer. |
| **Оркестрація контейнерів (Container Orchestration)** | Автоматизоване керування життєвим циклом контейнерів (розгортання, масштабування, балансування навантаження, відновлення після збоїв). Приклади: Kubernetes, Docker Swarm. | DevOps Engineer, Kubernetes Administrator (CKA), Cloud Engineer. |
| **Live Migration (Гаряча міграція)** | Технологія переміщення працюючої віртуальної машини з одного фізичного сервера на інший без зупинки її роботи та переривання обслуговування користувачів. | System Administrator, Data Center Engineer, Cloud Operations Specialist. |
| **Ephemeral Environment (Ефемерне середовище)** | Тимчасове, динамічно створюване середовище (зазвичай у контейнерах), яке існує лише під час виконання конкретного завдання (наприклад, проходження тестів) і знищується одразу після його завершення. | QA Automation Engineer, DevOps Engineer, Release Manager. |
| **GPU Passthrough** | Технологія, яка дозволяє безпосередньо передавати фізичний графічний процесор (GPU) від хост-машини до гостьової віртуальної машини чи контейнера для максимальної продуктивності обчислень. | MLOps Engineer, AI/ML Engineer, High-Performance Computing (HPC) Specialist. |
